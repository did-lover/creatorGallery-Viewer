# Creator Gallery Viewer

Dropbox に保存した画像・動画を、**クリエイター別 → 投稿別 → 縦積み**で見るための自分専用ギャラリーです。
`index.html` と `dropbox.js` だけで動く静的サイトで、GitHub Pages に置いて iPhone からも見られます。

- サイト自体は GitHub Pages で公開されますが、**中身は Dropbox にログインした本人にしか表示されません**（画像・ファイル名はリポジトリにもサーバーにも置きません）。
- 認証は OAuth 2.0 PKCE です。サーバー・クライアントシークレットは不要です。
- 一覧は端末内（IndexedDB）に保存し、2回目以降はすぐに表示 → 変更分だけ裏で更新します。

---

## 1. Dropbox アプリを作る

1. https://www.dropbox.com/developers/apps を開き、**Create app** を押す。
2. 次のように選ぶ。
   - **Choose an API**：`Scoped access`
   - **Choose the type of access**：
     - `Full Dropbox` … 既存のフォルダ（例 `/creators`）をそのまま読む場合（おすすめ）
     - `App folder` … `/アプリ/<アプリ名>/` の中だけを読む場合
   - **Name your app**：好きな名前（他の人と重複しない名前）
3. **Permissions** タブで次の2つにチェックを入れ、下の **Submit** を押す。
   - `files.metadata.read`（フォルダ・ファイルの一覧）
   - `files.content.read`（サムネイル・画像・動画の取得）
4. **Settings** タブで次を確認・設定する。
   - **App key** をコピーする（後で `dropbox.js` に貼る。この値は公開されても問題ありません）
   - **OAuth 2 → Redirect URIs** に、公開するページの URL を追加する（次の項目を参照）
   - **Allow public clients (Implicit Grant & PKCE)** が `Allow` になっていること

> アプリは「Development」状態のままで使えます（自分のアカウントで使う分には本番申請は不要です）。

### リダイレクトURI の登録

GitHub Pages の URL を、**末尾のスラッシュまで含めて**そのまま登録します。

```
https://<GitHubのユーザー名>.github.io/<リポジトリ名>/
```

例：`https://taka.github.io/creatorGallery-Viewer/`

- ユーザー名の部分は**小文字**で登録してください（GitHub Pages の URL は小文字になります）。
- `.../index.html` で開いた場合も、送るリダイレクトURI は末尾の `index.html` を外した形（`.../`）になるので、登録は上の1つで足ります。
- 自分の Mac で試すなら `http://localhost:8000/` も追加しておきます（後述）。

## 2. dropbox.js を設定する

`dropbox.js` の先頭にある定数を書き換えます。

```js
const DROPBOX_APP_KEY = "ここに App key";   // 空のままだと Dropbox を使わず、data.js / サンプルで動く
const ROOT_PATH = "/creators";              // 読み込むフォルダ。"" は Dropbox 全体
const FULL_RES = false;                     // true で投稿内の画像を原寸表示（通信量が増える）
```

- `ROOT_PATH` は Dropbox 上のフォルダのパスです（先頭は `/`、大文字・小文字は区別しません）。
  - `App folder` を選んだ場合は、アプリ用フォルダからの相対パスです（そのフォルダ自体なら `""`）。
  - `""`（Dropbox 全体）にすると、全ファイルを走査するので初回の取得に時間がかかります。**画像を置いたフォルダを指定するのがおすすめ**です。
- `ROOT_PATH` はコードに書くので、公開リポジトリでは誰でも見られます。見られて困る名前は避けてください。
- トップの見出しには `ROOT_PATH` の最後のフォルダ名が表示されます。

### フォルダ構成

```
<ROOT_PATH>/
  <クリエイター名>/
    cover.jpg                    ← 任意。クリエイターのカバー専用（投稿にはならない）
    20240101-ひとこと.mp4         ← クリエイター直下のファイルは、1ファイル＝1投稿として表示
    <投稿フォルダ名>/             ← 例「20240301-タイトル」
      001.jpg
      002.png
      clip.mp4
      sub/003.jpg               ← さらに深いフォルダの中身も、この投稿にまとめて表示
```

- **日付**：投稿フォルダ名（直下のファイルの場合はファイル名）の先頭が `YYYYMMDD-`（`_`・空白区切りも可）ならそれを使い、無ければ先頭のファイルの更新日を使います。画面では先頭の日付は表示しません。
- **クリエイター直下のファイル**：フォルダに入れていない画像・動画は、それぞれ1つの投稿になります（タイトルは拡張子を除いたファイル名）。`cover.*` という名前の画像だけはカバー専用です。
- **並び順**：フォルダ名・ファイル名の自然順（`2` < `10`）。画面右上で昇順・降順を切り替えられます。
- **カバー**：`cover.*` という名前の画像があればそれを優先します。無ければ、投稿は最初の画像、クリエイターは直下の画像 → 最新の投稿のカバーの順に自動で決めます。
- **対応形式**：画像 `jpg jpeg png gif webp bmp tif tiff heic heif avif`、動画 `mp4 mov m4v webm`。
  - サムネイルを作れない画像（HEIC・AVIF・20MBを超える写真など）は原寸で表示します。
- 名前が `.` で始まるファイル・フォルダ（`.DS_Store` など）と、上記以外の拡張子のファイルは無視します。

## 3. GitHub Pages で公開する

1. `dropbox.js` を設定したら、リポジトリにコミットして push する。
   - `data.js` などの実データ由来のファイルは `.gitignore` でコミットされないようにしてあります。
2. GitHub のリポジトリで **Settings → Pages** を開く。
3. **Build and deployment → Source** を `Deploy from a branch` にし、**Branch** を `main` / `/(root)` にして **Save**。
4. 1〜2分ほどで `https://<ユーザー名>.github.io/<リポジトリ名>/` が表示されるようになります。
5. 開いて「Dropbox に接続」を押し、Dropbox の画面で許可すると一覧の取得が始まります。

> 無料プランで GitHub Pages を使う場合、リポジトリは Public にする必要があります。上に書いたとおり、公開されるのはプログラムだけで、画像やファイル名は公開されません。

### 自分の Mac で試す場合

```bash
cd creatorGallery-Viewer
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開きます（Dropbox のリダイレクトURI に `http://localhost:8000/` を登録しておく）。

- `http://192.168.x.x:8000` のような **LAN内のIPアドレスでは動きません**。Dropbox の認証には HTTPS（または localhost）が必要なためです。iPhone からは GitHub Pages の URL で開いてください。

## 4. iPhone のホーム画面に追加する

1. iPhone の **Safari** で GitHub Pages の URL を開く。
2. 共有ボタン（□に↑）→ **ホーム画面に追加** → 追加。
3. ホーム画面のアイコンから開き、**その中で「Dropbox に接続」を押す**。

- ホーム画面から開いたアプリと Safari では、ログイン状態や保存した一覧が**別々**です。ホーム画面アプリで使う場合は、アプリの中で接続してください。
- ホーム画面アプリにしておくと、保存した一覧が自動で消されにくくなります（Safari のタブだけで使っていると、しばらく開かなかった時に端末内のデータが消えることがあります）。

## 5. 使い方のメモ

- **初回**はファイル数に応じて一覧の取得に時間がかかります（取得した件数が表示されます）。2回目以降は保存した一覧ですぐ表示されます。
- Dropbox に追加・削除した内容は、**起動した時**と、**アプリに戻って前回の確認から10分以上たっている時**に、裏で反映されます。今見ている画面に関係する変更があった時だけ、読んでいた位置のまま再描画します。
- **画像の枠**：Dropbox の一覧からは画像の縦横比が取れないため、最初は 3:4 の枠で表示します。一度表示した画像は比率を覚え、次にその画面を開いた時から正しい枠になります。
- 一覧・カバーは小さめのサムネイル、投稿内の画像は大きめのサムネイルで表示し、通信量とメモリを抑えています。
  - **iPhone・iPad など**（タッチ操作が主の端末）は最大 1024px、**Mac など**は最大 2048px。iPhone は使えるメモリが少ないため、画像の多い投稿でも落ちにくいよう小さめにしています。
  - 原寸で見たい場合は `FULL_RES = true` にします（iPhone では重くなります）。
- **大きいファイル**：サムネイルを作れない画像（20MBを超える写真・GIF、HEICなど）のうち 15MB を超えるものは、自動では読み込まず「タップで表示」の枠を出します。タップすると原寸を読み込みます。
- **動画**：画面に近づいた動画だけを再生できる状態にし、離れた停止中の動画は解放します（再生中の動画はそのまま）。
- **素早くスクロールした時**：通り過ぎてしまった画像は、取得を取り消して通信とメモリを節約します。
- **ログアウト**：トップ画面の右上のボタン（出口のマーク）。Dropbox との接続を取り消し、この端末に保存したトークン・一覧のキャッシュを削除します。

## 6. よくあるエラー

### `redirect_uri_mismatch`（Dropbox の画面でエラーになる）
Dropbox に登録したリダイレクトURI と、開いているページの URL が一致していません。
- `https://<ユーザー名>.github.io/<リポジトリ名>/` を**末尾のスラッシュまで**そのまま登録しているか
- ユーザー名が**小文字**になっているか、`https` になっているか
- ローカルで試している場合は `http://localhost:8000/`（ポート番号まで同じ）を登録しているか

### 429（too_many_requests）
Dropbox への要求が短時間に多すぎる時に返るエラーです。`dropbox.js` は Dropbox が指定した秒数だけ待って**自動で再試行**します。初回に大量のサムネイルを読む時に起きやすく、少し待てば表示されます。頻繁に起きる場合は、一覧をゆっくりスクロールしてください。

### 動画が再生できない
- 動画は Dropbox の一時リンク（有効期限 約4時間）で再生しています。期限切れで失敗した時は**自動で1回取り直します**。それでも再生できない場合はページを再読み込みしてください。
- iPhone で再生できる形式は主に `mp4`（H.264 / HEVC）と `mov` です。`webm` は端末によって再生できません。
- 動画のサムネイル（プレビュー画像）は Dropbox の API で取得できないため表示されません。再生ボタンを押すと読み込みが始まります。

### 「〜というフォルダが見つかりません」
`ROOT_PATH` が Dropbox 上のフォルダと一致していません。`App folder` を選んだ場合は、アプリ用フォルダからのパスになります。

### 「Dropbox アプリの権限が足りません」
App Console の **Permissions** で `files.metadata.read` と `files.content.read` にチェックを入れて **Submit** し、ログアウト → もう一度接続してください（権限の変更は再接続で反映されます）。

### 「HTTPS（または http://localhost）で開いてください」
LAN内のIPアドレスなど、HTTPS ではない URL で開いています。GitHub Pages の URL か `http://localhost:8000/` で開いてください。

### 更新したのに古い画面のまま
GitHub Pages はファイルを最大10分ほどキャッシュします。少し待つか、強制再読み込み（Mac の Safari は `⌘ + Option + R`）をしてください。

### コンソールに `data.js` の 404 が出る
`data.js` はローカル用のデータファイルで、Dropbox モードでは使いません。無視して問題ありません。

## 仕組み（開発メモ）

| 処理 | 使う API | 備考 |
|---|---|---|
| 一覧の取得 | `files/list_folder`（recursive）＋ `/continue` | カーソルを保存し、2回目以降は差分だけ取得。カーソルが無効なら全件取り直し |
| 一覧・カバーの画像 | `files/get_thumbnail_batch` | 25件ずつまとめて取得、同時2本まで |
| 投稿内の画像 | `files/get_thumbnail_batch`（iPhone等 w1024h768／Mac等 w2048h1536） | `FULL_RES = true` で `files/get_temporary_link`（原寸） |
| 動画・サムネ非対応の画像 | `files/get_temporary_link` | 有効期限の10分前に取り直す |

- データには実URLではなく擬似URL（`dbx:<パス>#thumb` / `#cover` / `#full` / `#orig` / `#video`）を入れておき、`window.resolveSrc()` が表示の直前に実URLへ変換します。
- 429・5xx は待って再試行、401 はトークンを更新して1回だけ再試行します。
- 取得の要求は送る直前に「その画像がまだ画面の近くにあるか」を確かめ、離れていれば取り消します。
- IndexedDB には生の一覧（ファイル・フォルダ情報）とカーソルだけを保存し、表示用のデータは起動時に作り直します（保存・読み込みのメモリを抑えるため）。
- トークンは localStorage、一覧・カーソル・画像の縦横比は IndexedDB にだけ保存し、ログには出しません。
- `DROPBOX_APP_KEY` が空のときは `dropbox.js` は何もせず、`data.js`（ローカルの build.py が生成）またはサンプルデータで動きます。
